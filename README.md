# Obiimy — лендинги, B2B-сторінки, рекламні банери

Проєкт для українського бренду шовкових аксесуарів [Obiimy](https://obiimy.world/): авторські принти художниці Світлани Сніжко, 100% італійський шовк, виготовлено в Україні.

- Репозиторій: `id-mozart/obiimy-landing`, гілка `main`
- Живий сайт (Railway): https://obiimy-landing-production.up.railway.app — головна сторінка-хаб зі всіма версіями
- Стан на 01.10.2026. Новий діалог з Claude починати з цього файлу й `CLAUDE.md`.

## Правила роботи (від клієнта)

- Не вигадувати факти, знижки, відгуки, кейси, строки, мінімальні тиражі. Усе, чого немає на obiimy.world, пишемо як «уточнимо в розрахунку». Перевірені факти — `review/SITE-FACTS.md`, реліз колекції SOLO — `review/SOLO-RELEASE.md`.
- Ціни — тільки роздрібні з obiimy.world.
- Фото — тільки справжні з obiimy.world. Людей і товари не генеруємо, нових фото не робимо. Походження фото паризької серії (`photo/paris-*`) не підтверджене, тому на нових сторінках її не використовуємо.
- Паролі та секретні ключі користувач вводить сам. Shopify-доступи лежать лише в `~/.config/obiimy/shopify.env`; їх не друкуємо й не комітимо.
- Аудит: кожну нову сторінку чи банер перевіряють агенти-експерти. Ітеруємо, доки кожен не поставить щонайменше 8,5/10 (див. «Аудит» нижче).
- Деплой збираємо пакетом, а не після кожної дрібниці: деплой триває 5–12 хвилин, а паралельні `railway up` стають у чергу.
- Підпис коміту закінчується рядком `Co-Authored-By: Claude …` (модель сесії).

## Що де лежить

| Шлях | Що це |
|---|---|
| `*.html` у корені | Джерела сторінок без `<!DOCTYPE>`. Згенеровані — не редагувати руками, правити генератори в `src/` |
| `src/build-*.py` | Генератори сторінок (див. нижче) |
| `src/imgs.py` | `img()` — `<img>` з `srcset` 480/800/1200 (WebP-варіанти поруч із файлом); `typo()` — типографіка |
| `build-site.py` | Збирає `site/`: обгортає сторінки, копіює `img/ photo/ tex/ brand/`, PDF, робить мініатюри (headless Chrome) і хаб `index.html`, викликає `ads/build_gallery.py` |
| `site/` | Те, що деплоїться (`npm start` → `serve site`) |
| `img/`, `photo/`, `brand/`, `tex/` | Фото з obiimy.world, логотипи, текстури; `img/cut/` — вирізки товарів із серії SOLO |
| `ads/` | Рекламні банери й галерея (див. нижче) |
| `review/` | Факти, аудит-брифи (`review/pp/AUDIT-*.txt`), скриншоти для аудиторів (`review/pp/team/`, `shop/`, `main/`, `gallery/`) |
| `shopify/` | Скрипти Admin API для shop.obiimy.world (`shop.py`, `apply_fixes.py`, `fix_products.py`, бекапи) |

## Лендинги бренду (10 версій)

Maison (головна), Garden (3D-арт), Journal, Campaign, Lookbook, Studio, Noir, Form, Art, Classic. До кожної є приклад сторінки товару (`product-<версія>`; генератор `src/build-products.py`, у WebGL-версіях — 3D-в'ювер `src/silk-engine.js`). Скіни (кольори, шрифти) — `SKINS` у `src/build-products.py`.

## B2B-сторінки

Спільний кіт — `src/build-b2b.py`: `hero`, `form_html` (форма через `mailto:`), `shell`, `price`, список `OTHERS`, групи футера `GROUPS`.

**Подарунки для команди (HR, офіс-менеджери).** Головні:

| Сторінка | Генератор | Роль |
|---|---|---|
| **b2b-team-main** | `src/build-b2b-team-main.py` | Головний вхід (скорочено 01.10 на прохання клієнта). Hero (SOLO) → три причини → колекція SOLO → чотири рівні подарунка → увесь асортимент (фото, назва, «від») → персоналізація → форма. Каталог зі списком, план на рік, привітання, FAQ прибрані (код секцій лишився у файлі) |
| **b2b-sets-gallery** | `src/build-b2b-sets-gallery.py` | Набори: 8 родин із чіпами принтів (кожен принт іде в список зі своєю ціною), фільтр за нагодою, «свій набір», що впізнає готовий, таблиця порівняння |
| **b2b-team-details** | `src/build-b2b-sets-gallery.py` | Переваги й деталі: шовк, формати й ціни, колекції, пакування, догляд, привітання, доставка й оплата (з чек-листом для бухгалтерії), сертифікати, бренд |

Варіанти (живі, у хабі; у футері не рекламуються): `b2b-team` (шлях людини + калькулятор), `b2b-team-quiz`, `b2b-team-card`, `b2b-team-plans` — `src/build-b2b-team.py`; `b2b-team-catalog`, `b2b-team-budget`, `b2b-team-offer` — `src/build-b2b-team-shop.py`.

Рекомендація аудиторів щодо каналів:
- main — основний вхід для всіх каналів;
- budget — реклама з бюджетом у запиті;
- offer — прямі контакти й відповідь на вхідний запит;
- sets-gallery — запити «подарункові набори»;
- details — пересилання фіндиректору й бухгалтерії;
- team, card, plans, catalog поглинула main — їх можна перевести в редиректи.

Дані команди-серії:
- **Каталог і нагоди** — `CATALOG` (19 позицій, `neutral` = «підходить усім»), `STAGES` (8 нагод), `PLANS`, `CARDS` у `src/build-b2b-team.py`.
- **Спільна логіка списку** — `LIST_JS` у `src/build-b2b-team-shop.py`. Блоки у форму пишуться між маркерами `=== … ===`, поле «Із них не носять аксесуари» ділить: шовк — одним, речі «усім» — іншим.

**PDF для HR:** `obiimy-podarunky-dlia-komandy.pdf`, 8 сторінок (01.10, редизайн під SOLO-креативи, шрифт Playfair Display): обкладинка, бренд, три причини, колекція SOLO, чотири рівні, увесь асортимент, персоналізація, контакти. Дані спільні з `b2b-team-main`: `PERKS`, `SOLO`, `TIERS`, `ASSORT`, `PERS` у `src/build-b2b-team-main.py`; фото SOLO — `photo/solo/` (копії з `ads/solo/src`). Генерується так: `python3 src/build-team-pdf.py` → `team-deck.html` → PDF через headless Chrome. На сторінках є посилання на нього.

**Сторінки чотирьох рівнів (01.10):** `b2b-set-twilly`, `b2b-set-scarf-ring`, `b2b-set-mask`, `b2b-set-scarf-twilly` — `src/build-b2b-sets4.py`, дані `SETS4` у `src/build-b2b-team-main.py` (фото на моделі з SOLO-зйомки + товар, деталі, чотири способи носити). У хабі їх немає (`HIDDEN` у `build-site.py`), посилання — з секції рівнів на `b2b-team-main`. У деці — по сторінці на кожен рівень. Секція рівнів на лендингу і сторінка в деці зараз у трьох варіантах (A — редакційний, B — чотири фото на моделі, C — два на два); після вибору клієнта зайві прибрати (`tiers_a/b/c` у генераторі лендингу, блок «# 5 four tiers» у `src/build-team-pdf.py`).

**Службова сторінка для менеджерів:** `/kp` (`src/build-kp.py` → `kp.html`; у `build-site.py` список `HIDDEN` — не в хабі, не в меню й футері). Конструктор комерційної пропозиції за зразком КП клієнта: обкладинка → фото → таблиця зі знижкою → пакування й персоналізація → контакти. Ціни з каталогу (роздрібні), знижка, строки, доставка — вписує менеджер; стан у хеші адреси (кнопка «Посилання»), друк → A4 PDF.

**Інші B2B:**
- `src/build-b2b.py`: newyear, horeca, wholesale, calendar, certificates, agencies, speakers, en.
- `src/build-b2b-extra.py`: unboxing, monoprint, atelier, garden.
- `src/build-b2b-sets.py`: каталог наборів `b2b-sets`.
- PDF-лукбук: `src/build-lookbook.py`.

## Рекламні банери (`ads/`)

- Серії SOLO у `ads/solo/`:
  - генератори `build4.py`, `build6.py`, `build8.py`, `build9.py` → `soloN.html`;
  - рендер: `cd ads && ADS=solo/soloN.html OUT=solo/outN [ONLY=id1,id2] node render.mjs`.
- Паризька серія: `ads/ads2.html` → `out2` → `final2/`.
- Галерея `ads/build_gallery.py` → `site/creatives.html`:
  - показує лише банери зі списку `ads/keep.txt` (24 відібрані, порядок = порядок показу);
  - решта лежить в архіві `creatives-archive.html`, він не має посилань;
  - чекбокси вибору, попап-перегляд;
  - посилання `#sel=` показує тільки вибрані банери.

## Збирання й деплой

```bash
cd src && python3 build-b2b-team.py && python3 build-b2b-team-shop.py && python3 build-b2b-team-main.py && python3 build-b2b-sets-gallery.py && cd ..
python3 build-site.py
```

```bash
git push -q origin main && railway up -y -c --service obiimy-landing
```

- Повне збирання (`build-site.py`) триває кілька хвилин через мініатюри. Для швидкої перевірки однієї сторінки досить обгорнути її функціями `wrap` і `relink` з `build-site.py`.
- Перевірити деплой: `railway deployment list --service obiimy-landing`.
- `.railwayignore` виключає `photo/ img/ tex/ brand/ src/ shopify/ *.pdf` у корені та **оригінали JPG креативів `site/creatives/*/*.jpg`** (01.10: завантаження 170–200 МБ обривалося по таймауту; на проді галерея показує лише WebP-прев’ю, посилання «JPG ↓» на проді не працюють — оригінали лишаються в репозиторії). Архів тепер ~45 МБ.
- Локальна перевірка: `python3 -m http.server 8765` з кореня → `http://localhost:8765/site/<slug>.html`. Puppeteer-core лежить у `review/pp/node_modules`, Chrome — у `/Applications`.

## Аудит

- Брифи: `review/pp/AUDIT-TEAM.txt` (команди-серія з усіма раундами), `AUDIT-SOLO*.txt` (банери), `AUDIT-SETS*.txt`.
- Агенти-експерти для B2B:
  - арт-директор;
  - бренд-менеджер і фактчекер;
  - UX і конверсія;
  - B2B-маркетолог;
  - HR-директор (персона).
- Для банерів — інші шість експертів: арт-директор, дизайнер, рекламіст, бренд-менеджер, експерт із реклами подарунків, fashion-експерт.
- Порядок роботи:
  1. дописати в бриф, що змінилося за раунд;
  2. перезняти скриншоти;
  3. надіслати агентам;
  4. повторювати, доки кожен не дасть ≥ 8,5.

Останні оцінки (≥ 8,5 у всіх п'яти експертів): b2b-team-main 8,5–8,8 (PDF 8,5–8,7), b2b-sets-gallery 8,5–8,7, b2b-team-details 8,6–8,7.

## Відкриті питання до клієнта

1. Корпоративний кейс із цифрою (можна без назви компанії).
2. Справжнє фото листівки в подарунку та фото пакування окремих речей.
3. Святкова коробка для всіх наборів: на сайті вона підтверджена лише для «Твіллі та резинка» і «Трьох твіллі».
4. Процес корпоративного замовлення:
   - відправка кожному співробітнику за списком;
   - документи й ПДВ;
   - графік оплати;
   - мінімальне замовлення.
5. Допуск розміру 0–2,5 см (є в аудит-нотатках, у SITE-FACTS немає) і адреса сторінки обміну й повернення.
6. Домен для лендингів замість railway.app — для PDF і довіри.
7. Єдині фото наборів на одному фоні.
8. Назва принта: «Тиша» на сайті чи «Тиша всередині» в релізі.
9. Походження фото паризької серії.
10. Формати принтів, позначені «?» у таблиці SITE-FACTS.
