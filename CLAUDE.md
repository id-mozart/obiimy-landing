# Obiimy — контекст для Claude

Повний опис проєкту, команд і відкритих питань — у `README.md`. Прочитай його на початку нової сесії.

## Як працювати з цим користувачем

- Мова спілкування — російська. Тексти на сторінках і банерах — українською.
- Користувач пише коротко й чекає результату; між діями достатньо коротких статусів. Коли зроблено — дай посилання на живу сторінку й коротку таблицю оцінок експертів.
- «Деплой» означає: зібрати `site/` (`python3 build-site.py`), закомітити й `git push` у `main` — Railway сам збирає прод із GitHub (з 07.10.2026; `railway up` більше не потрібен). Потім дочекатися `SUCCESS` у `railway deployment list --service obiimy-landing` і перевірити живу сторінку через curl. Пушити пакетом: кожен пуш — нове збирання на кілька хвилин. Прод — проєкт `obiimy-landing` у воркспейсі «id-mozart's Projects»; статус деплою дивитися через API з токеном із `~/.config/obiimy/railway.env` (див. README, розділ «Збирання й деплой»).

## Жорсткі правила

- Не вигадувати факти, знижки, відгуки, кейси, строки, мінімуми, «найпопулярніше» тощо. Джерела: `review/SITE-FACTS.md`, `review/SOLO-RELEASE.md`. Чого там немає, пишемо як «уточнимо в розрахунку».
- Ціни — тільки роздрібні з obiimy.world. Фото — тільки справжні з obiimy.world: людей і товари не генерувати.
- Секрети (Shopify — `~/.config/obiimy/shopify.env`) не друкувати й не комітити. Паролі вводить сам користувач.
- Нові сторінки й банери проганяти через агентів-експертів, доки кожен не дасть ≥ 8,5/10. Склад експертів і порядок роботи — в розділі «Аудит» у `README.md`.

## Технічне

- Згенеровані HTML у корені руками не редагувати: правити генератори `src/build-*.py`, потім збирати сайт `python3 build-site.py`.
- Для швидкої перевірки однієї сторінки її можна обгорнути в `site/` через `wrap` і `relink` з `build-site.py`. Сайт локально: `python3 -m http.server 8765` → `localhost:8765/site/<slug>.html`.
- Скриншоти й функціональні перевірки — puppeteer-core з `review/pp/node_modules`. Chrome: `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`. Перед скриншотом довантажувати lazy-зображення.
- Після правок у JS запускати `node --check` для вбудованих `<script>`.
